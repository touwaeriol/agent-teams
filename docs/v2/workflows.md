# 工作流程（流程图）

用户在 设置 → 工作流程 里画流程图，写下一件事怎么做：每一步交给哪个岗位、先后顺序、哪些步骤并行、审查不通过退回到哪里。讨论串的组长拆任务时**参考**项目的流程（2026-11-28 定：只给组长参考，平台不按图自动展开任务，也不拦流程外的任务）。

## 数据（迁移 00540）

- `at_workflows`：用户级模板，`(user_id, name)` 唯一，每个用户最多一个 `is_default`、最多 20 个流程。
  - `steps`：`[{id, name, role, kind, instructions, x, y}]`，最多 30 个。`role` 是成员岗位的 key（如 `dev`）或 `lead`（组长自己做）；`kind` = `work` 做事 / `review` 审查 / `decision` 决策 / `approval` 等用户确认（这种步骤 `role` 为空）。`x`、`y` 只是画布位置。
  - `edges`：`[{from, to, kind, label}]`，最多 60 条。`kind` = `next`（然后）或 `reject`（不通过退回）。同一对步骤同一种连线只能有一条，不能连回自己。
- `at_projects.workflow`：`''` = 用户的默认流程，`none` = 不用流程，否则是流程 id。删除流程时选了它的项目回到 `''`。

一个步骤连出几条“然后”，这几步并行；几条“然后”指向同一步，它要等前面全部完成。

## 接口

`GET/POST /api/workflows`、`PUT/DELETE /api/workflows/{id}`（`internal/httpapi/workflows_routes.go`），保存时校验岗位必须在用户的团队里（成员岗位或 `lead`）。用户的第一个流程自动成为默认；设新的默认会取消旧的。项目用 `PATCH /api/projects/{pid}` 的 `workflow` 字段选流程。

## 生效

`orchestrator.systemAppend` 给组长（`tier = lead`）的系统提示末尾加一节“## 工作流程：<名称>”（`workflows.Render`）：一段怎么用的说明（每步建成对应岗位的任务、`depends_on` 体现先后和汇合、并行步骤不串起来、退回时开返工任务、等用户确认的步骤用 `ask_user`、流程外的情况可以调整但要说明），然后按“然后”连线的拓扑顺序列出步骤（岗位、类型、说明、然后 → / 不通过退回 →）。已经不在团队里的岗位会标出来，让组长换一个合适的。统筹和成员不收到流程。新的组长会话才读到改动。
