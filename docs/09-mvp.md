# 09 第一版范围

目标：一个人、两三台服务器，在 Web 上建项目、和统筹对话，看着员工把任务做完、推到 GitHub。

## 里程碑

### M0 · 技术验证（先做，结论写回本文）

逐条验证下面“需要先验证的事”，每条一个最小脚本。结论影响适配器和记忆的实现方式。

### M1 · 节点与员工

- 控制面骨架：登录、PostgreSQL、迁移、WebSocket。
- 守护进程：安装命令接入（SSH 安装放后面）、心跳、扫描 Claude Code、读额度、断线重连。
- 员工模板：内置统筹 / 架构师 / 开发 / QA / 开发负责人五个模板，可编辑。
- GitHub 连接（GitHub App 或访问令牌），仓库只接受 GitHub 链接。
- 项目：建项目、粘贴 GitHub 链接绑仓库、模板 × 节点数量矩阵、守护进程建员工目录。
- 页面：节点、添加节点、员工模板、项目列表 / 新建、项目设置、员工列表。

**完成标准**：在 Web 上建项目，几秒后两台节点上出现对应的员工目录，员工列表显示“空闲”。

### M2 · 任务执行

- Claude Code 适配器（stream-json）、统一事件、事件落库、时间线。
- 调度器：三层限制、`quota` 均衡、排队、粘性。
- 人在 Web 上手动建任务；停止 / 续跑 / 发消息。
- 权限请求 → 审批中心 → 答复回写。
- GitHub 凭证 helper、worktree、交付分支推送。
- 页面：任务、员工详情（时间线）、审批中心、Git 连接。

**完成标准**：手动建一个任务，员工在某个节点上完成并把交付分支推到 GitHub，途中的权限请求在审批中心放行。

### M3 · 统筹与对话

- 统筹员工、唤醒机制、`reply_user` / `update_plan` / `create_task` 等统筹工具。
- 项目对话页（计划卡片、派发、工作动态、对话内审批卡片）。
- 记忆：`remember` / `forget` / `write_handoff`、SessionStart 注入、80% 上下文提醒、项目知识与提升。
- 页面：项目对话、员工详情的记忆页签。

**完成标准**：在对话里提一个需求，统筹给出计划，确认后派给两名开发并行完成；中途重启一个员工的会话，它能接着做。

### M4 · 对外与可视化

- 对外 MCP（访问令牌）、MCP 接入页。
- 建 PR、交付区。
- 办公室页（先用简化的房间和人物，再换像素素材）。

**完成标准**：在本机的 Claude Code 里装上 MCP，用一句话建项目，在 Web 的办公室页看到员工在干活。

## 需要先验证的事

| # | 问题 | 影响 |
| --- | --- | --- |
| 1 | Claude Code `-p --input-format stream-json` 能否长驻、多次写入用户消息、中途打断；`--resume` 与之配合是否正常 | 适配器运行方式；不行就改用 Agent SDK 或 `--bg` + 收件箱 |
| 2 | `--permission-prompt-tool` 在 `auto` / `default` 模式下的触发范围；`-p` 模式下 AskUserQuestion 是否可用、PreToolUse 拦截是否有效 | 审批链路 |
| 3 | SessionStart 钩子的附加上下文在新开、`--resume`、自动压缩后是否都生效 | 记忆注入 |
| 4 | 同一系统用户下多个 `claude` 进程并发运行时，OAuth 令牌刷新是否会互相冲突 | 一个节点能稳定跑几个员工 |
| 5 | `claude -p /usage --output-format json` 在并发会话下的准确性和调用成本 | 额度均衡 |
| 6 | Claude Code 自带的按目录记忆：存在哪、能否关闭 | 记忆是否会出现两套 |
| 7 | git 凭证 helper 配 `useHttpPath=true` 时能拿到完整仓库路径；worktree 内是否继承 `GIT_CONFIG_GLOBAL` | Git 签发 |
| 8 | Codex app-server 的线程恢复、审批请求、MCP 配置方式 | Codex 适配器（M4 之后） |
| 9 | 所用 Claude Code / Codex 账号类型的使用条款是否允许这种多会话自动化用法（订阅账号与 API 账号可能不同） | 部署前确认 |

## 风险

- **账号额度和速率限制**：一个账号上同时跑多个员工加子代理，很容易触发限速。靠槽位、额度阈值和均衡缓解，第一版槽位默认保守（每节点 3）。
- **agent CLI 接口变化**：stream-json、钩子、app-server 都可能随版本变化。适配器集中处理，守护进程上报版本，控制面对不兼容的版本给出提示。
- **员工误操作**：第一版只有目录隔离。权限模式默认 `auto`，危险操作走 `must_human` 规则，仓库开分支保护。
